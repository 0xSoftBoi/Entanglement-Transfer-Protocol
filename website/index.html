What it guarantees

Four properties, one artifact

Each is individually well-understood. The product is the fusion — no open-source project or vendor ships all four as one verifiable custody workflow.

🔒

Post-quantum confidentiality

Sealed with ML-KEM-768 + XChaCha20-Poly1305 at a constant 1 KB overhead, independent of payload size — the harvest-now-decrypt-later defense for data that must stay secret for decades.

seal · send
📜

Tamper-evident provenance

Every capture is notarized into an RFC-6962 append-only Merkle log. Portable receipts prove inclusion; audit proves consistency — the notary never rewrote or forked history.

verify · audit · inspect
✍️

Two-party authenticity

The notary signs "it's in my log"; the capturing device signs "I captured this content, at this time." Pin either or both — an attacker's own log is rejected.

--operator · --expect-originator
🛰️

Delay-tolerant transport

Erasure-coded into n shards, any k reconstruct. Spray them over a satellite pass, tactical mesh, or data mule — no ARQ round-trip. Lose a third and still recover, byte-identical.

bundle · reassemble

The flow

Send. Transport. Receive.

Two commands wrap the whole pipeline. The reassembled blob is byte-identical, so the same receipt verifies it — provenance is untouched by the lossy transport.

sendseal · notarize · device-sign · erasure-bundle
→
lossy linksatellite pass · mesh · data mule — shards drop
→
receivereassemble · verify (pinned) · open
⚠ Fails closed. receive never writes plaintext if provenance doesn't verify — a wrong key, a tampered shard, or a forged receipt yields no output, not bad output.
